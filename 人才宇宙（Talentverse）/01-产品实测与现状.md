## 二、产品实际做什么

### 真实执行内核：桌面 RPA + 薄云后台（对照"爬 Boss 省人工"判定）
- **真实动作全部在"客户自己已登录的 Boss 直聘账号 + 本机 Chrome"里由桌面客户端执行**。官方 changelog（/api/downloads 实测返回）自曝实现：修复"Windows 打招呼『点名字反而点到头像』…打开简历改点名字元素，不再点 AXImage 头像"、"打招呼主循环…视口/身份护栏 + **dry-run 采简历**"、"候选人耗尽双平台根治"、"收简历/沟通时列表刷新拉回顶端"。→ 就是**在你 Boss 账号里逐一点候选人名字/开简历/打招呼/收简历的 UI 自动化**。
- manual 原文：自动招聘任务运行期间保持 Chrome 与网络连接、**不要在其他电脑重复登录同一 BOSS 账号**；AI 用**用户自备 DeepSeek API Key**（BYOK）。落地页用"自主执行/自进化/桌面端下沉"包装，刻意回避"爬取/反爬/浏览器自动化"，但下载中心客户端文件名直接是 *Bole-\*.exe/.dmg*。
- 客户端发布清单（已证实）：**Windows x64 1.3.22（Bole-1.3.22-windows-x64-setup.exe，35.6MB，2026-09-04）+ macOS universal 1.2.34（Bole-1.2.34.dmg，52.2MB，2026-09-01）**，附 SHA-256、系统要求、changelog。

### 四套界面（nginx 静态分发，同一 Supabase/API 后端）
1. 营销站 `/`、`/product.html` `/manual.html` `/download.html` `/pricing.html` `/roadmap.html`：讲"一套系统三件事：自主执行/自我进化/人才储备"。
2. **登录看板（个人/员工候选人台，`/login`）**：候选人表——姓名/学校/学历/**岗位(实际是很脏的抓取文本)**/**评分(0-100)**/状态(已收集·已回复·已约面·不合适·已搁置)/资料标识(手机·微信·PDF)。抽屉=档案：联系方式一键复制、评分结论、面试安排、附件简历(PDF/正文)、**沟通记录气泡**。支持筛选、批量导出 CSV、批量移入回收站。**非 demo 账号直读 Supabase `candidates` 表（RLS 按租户）**；`?demo=1` 才是内置 mock。
3. **企业管理版（`/enterprise.html`）**：企业概览、员工数据拆分、创建员工(5 席位)、企业候选人、客户端下载中心（推断，进入逻辑在 JS）。
4. **平台管理控制台（`/admin.html`）**：运营概览、**跨租户候选人检索**、企业管理、账号管理(创建/停用/重置密码/改邮箱/删号/永久删除/升管理员)、企业审计+系统审计、服务器监控(ECS+NAS)、NAS 归档管理。

### 云数据层（本轮的实测重点，纠偏）
- **云不是"纯 Mock / 0 DB"**：Supabase 里有真实 `candidates` 表（本次实测 6,685 行，RLS 租户隔离），PDF 原件存 **NAS**（管理端 UI 直标"PDF 原件已归档到 NAS"；云 `cloud_pdfs=0`）；`/api/*` 管理网关做聚合/鉴权/审计。桌面端在本地 Boss 会话执行、把候选人记录+简历同步上云是这套多租户后端的事实来源。

## 三、技术栈 / 架构（实测）
- 域名 hanxai.cn / bole.hanxai.cn → nginx（HSTS 开）；DNS 回 fake-ip（本地代理）。
- 营销站=手写静态 HTML/CSS/JS；控制台=原生 JS/Vite SPA + CDN `@supabase/supabase-js@2`。
- 认证/用户：Supabase Auth GoTrue；JWT `app_metadata.bole_role` 区分 platform_admin / enterprise_admin / enterprise_employee / personal。
- 数据库：Supabase Postgres（`candidates` 等表，RLS 租户隔离；个人台直读）。
- 管理 API：同源 `/api/*`，Bearer 鉴权；未带 token 返回 `{"code":"REAUTH_REQUIRED"}`；运行时框架外部不可见（推断 Node 系，未证实）。
- 文件：NAS（QNAP 类，管理端 hostname 样式），归档 837 份 PDF。
- 客户端：Windows 10/11 + macOS 12+，驱动 Chrome，LLM=客户自备 DeepSeek Key。
- 工程细节：多租户(企业-员工-席位)、企业+系统双审计日志、删除=回收站留≥30 天 + 永久删除、CSV 导出防公式注入、登录按个人/企业版分流。

## 五、它攒了什么可迁移数据（→ 能否当"能力档案/证据"种子）
**已攒（真实）**：① 候选人触点宽表 ×6,685（姓名+学校+学历+岗位文本+手机/微信/邮箱+沟通记录+状态+评分），含 837 份 PDF 原件入 NAS；② 多租户组织壳（企业-管理员-员工-席位+审计）；③ "跑 Boss 的桌面 RPA + 状态机/护栏"工程 + 带 evidence 维度的评分雏形 + DeepSeek 话术。

**判断：不能直接当 Talentverse"证据型能力档案"的种子，只能当"联络名单 + 原材料"。**
- 数据本质是 **Boss 候选人的个人数据**（联系方式、聊天原文、简历 PDF），用途受限：授权/合规（候选人未授权"永久人才库"）、Boss 平台红线（04）、以及**没沉淀自己产出的能力证据**（评估覆盖弱、字段脏、无轨迹/作品/验证链路）。
- 真正可带走的是**雇主侧资产**：哪些企业/招聘者在招、招什么岗、自动化跑多深、哪类账号被风控——这是新楔子的获客与需求情报。

## 六、风险清单（结合实测）
1. **Boss 依赖=账号级命门**：执行在客户自己的 Boss 账号+Chrome 上；主页自陈仅 BOSS"跑通全自动"，猎聘建设中、智联规划中。changelog 已现多次"Boss 改点击目标就点歪"的修复。
2. **风控/封号是高频现实（非假设）**：manual 明写"非本人常用设备或网络环境下登录，容易触发 BOSS 直聘平台自身的风控…账号受限或自动操作被拦截"；不得多机同登一 Boss 账号 → 每客户需"干净 Boss 号+环境"，扩张阻力+Ops 负担；封号成本转嫁客户，不可规模化。
3. **诉讼/数据红线**（见 04）：6,685 条带手机/微信/邮箱/聊天原文 + 837 份简历 PDF 原件 = 复制 Boss 关系资产；产品页明文"BOSS 直聘·已接入"。
4. **改版脆弱 + 无本体抽取**：`job_position` 脏乱证明无稳定 Schema，页面一变就坏。
5. **复利假说未证实**：约面 2 条、NAS 停更 3 周、评分几乎未落地——"越跑越准/储备越厚"是叙事非数据。
6. **营销 overclaim / 占位价**：宣称 AI 面试/图谱/Open API/私有化；定价页自标"上线前请替换为真实价格/占位口径"；无在线付费，仅"预约演示+14 天试用"，商业化未落地。
7. **个人数据合规成本**：候选人数据跨用途（自建库）撞 PIPL 目的限定；后端已有回收站/审计/脱敏意识，但受制于 Boss 侧红线。

## 七、与"AI 验证型猎头"新楔子的关系
- **可复用：雇主客户与需求**——5-6 家试点企业+十余真实招聘者，都是"要招人、已肯在自己电脑上跑自动化"的雇主，正是"AI 验证型猎头"的种子（同一批人同一需求：要人+要判断）。
- 可复用工程：多租户后台/审计/回收站 + 桌面执行态（人在电脑上跑=有真实环境去抓候选人公开行为/作品做验证）+ **带 evidence 依据维度的评分雏形**（changelog 证实已实现）＝ 验证型评估的底座。
- 带不过去/要重建：**"以 Boss 数据为原料"的采集资产不能当"能力证据"源**；验证型楔子要候选人**自己产生的证据**（作品/开源/时间线/真人多轮），与 6,685 条 Boss 抓取行几乎不重叠——顶多作冷启动名单去触达，验证结论须重新生产。
- 结论：bole = **过渡现金流 + 雇主触达入口 + RPA/评分工程**；真身要走"验证+结果+信任"，别再加深 Boss RPA 依赖。

---

## 八、一句话总结
真后端、真数据、真工程，但本质仍是**"单 Boss 账号桌面爬虫 + 记账本"**：6,685 条触点数据却几乎没产生约面（2 条）、AI 评分绝大多数未跑、NAS 归档已停 3 周、无自然客户（企业多为自建试点）；最有价值的是**一批已在用它的雇主/招聘者 + 桌面执行&审计工程 + evidence 评分雏形**——这恰是"AI 验证型猎头"的种子客户与工程底座，前提是把"能力证据"的采集从 Boss 里搬到候选人自己的动作上来。
